# AUV ATKP 风格通信协议剖面

本文描述当前仓库代码实际使用或尝试使用的帧结构，并记录它与《匿名通信协议》V7.16 参考手册之间的差异。发生冲突时，应以冻结后的 STM32 与 ROS 同一版本源码、字节抓包和回环测试结果为准。

## 基本帧格式

```text
AA FF ID LEN DATA[LEN] SC AC
```

| 字段 | 长度 | 含义 |
| --- | ---: | --- |
| `AA` | 1 Byte | 固定帧头 |
| `FF` | 1 Byte | 当前工程固定使用的第二帧头／广播地址字节 |
| `ID` | 1 Byte | 消息功能码 |
| `LEN` | 1 Byte | 数据区长度 |
| `DATA` | LEN Bytes | 小端序数据区 |
| `SC` | 1 Byte | 从 `AA` 到数据区结束的逐字节累加低 8 位 |
| `AC` | 1 Byte | 每次更新 `SC` 后继续累加所得的低 8 位 |

校验伪代码：

```text
sc = 0
ac = 0
for byte in frame[0 : 4 + LEN]:
    sc = (sc + byte) & 0xFF
    ac = (ac + sc) & 0xFF
```

## 关键消息及版本差异

| ID | 参考协议含义 | 当前仓库实现 | 状态 |
| --- | --- | --- | --- |
| `0x01` | 6 轴惯性数据和状态，13 Bytes | `sendacc_gyro()` 发送 6 个 `int16` 加 `uint32` 时间戳，共 16 Bytes | 项目扩展 |
| `0x03` | 欧拉角，3×`int16` 加状态 | `sendSenser()` 发送 3 个角度量和状态 | 基本兼容，需确认轴顺序和符号 |
| `0x05` | 融合高度、附加高度和状态，共 9 Bytes | `sendDepth()` 发送深度相关数据 | 长度接近，语义和打包代码需测试 |
| `0x08` | X、Y 位置偏移，2×`int32`，共 8 Bytes | `sendPOS()` 发送 X、Y、时间戳和 Z，共 16 Bytes | 项目扩展 |
| `0x41` | 7×`int16` 实时控制量，共 14 Bytes | ROS 下发节点构造相同长度的控制帧 | 字段位置与校验尚未对齐 |
| `0xF1`～`0xFA` | 用户自定义调试数据 | STM32 使用 `0xF1`、`0xF2` 等发送项目数据 | 需逐帧补充字段表 |

## `0x41` 实时控制帧

参考手册定义的数据区顺序为：

```text
CTRL_ROL, CTRL_PIT, CTRL_THR, CTRL_YAWDPS,
CTRL_SPD_X, CTRL_SPD_Y, CTRL_SPD_Z
```

每项均为小端 `int16`。当前 `serial_send_losdata.cpp` 把 `LOS × 100` 写入第一个 `int16`，只正确计算普通累加校验，并把 `AC` 固定为 0；当前 STM32 解析版本则检查 SC/AC，并从其他字段读取航向控制量。因此该帧尚不能作为已对齐接口。

推荐统一为：

1. 明确 LOS 表示目标航向角、航向角速度还是横向导引量。
2. 冻结 7 个字段的物理含义、比例、单位和有效范围。
3. 同时实现 SC 与 AC。
4. 使用固定十六进制测试向量做 STM32—ROS 双向回环。
5. 执行器断电条件下完成异常帧、半帧和粘包测试。

## 接收端要求

- 解析状态必须跨多次串口 `read()` 保留，不能假设一帧对应一次读取。
- 必须检查 `LEN` 上限，避免越界。
- SC 或 AC 不匹配时丢弃整帧并记录错误计数。
- 串口设备名、波特率和超时时间应改为 ROS 参数。
- 记录原始帧时需附时间戳、方向和端口信息，方便复现。

## 第三方资料边界

《匿名通信协议》仅用于理解通用帧结构和部分标准 ID。本仓库公开文档应维护自己的协议表，不复制第三方手册正文，也不把项目扩展描述成第三方标准内容。
